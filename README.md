A curated reproduction of [ProcVLM](https://github.com/RUCKBReasoning/ProcVLM), built from the archived code used for the completed training runs and aligned vLLM evaluation—not an export of a changing development checkout.

> **Scope:** ProcVQA training and original-vLLM evaluation. This is **not a strict, difference-free paper reproduction**: Stage 1 excludes unavailable-media groups, and processor pixel budgets differ from the official model. See the [reproduction boundaries](docs/REPRODUCTION.md#reproduction-boundaries).

## Quick start

Linux + NVIDIA GPUs + Python 3.10 are required for training/inference. Use **separate training and evaluation environments**; their `evqa` packages are intentionally different. Historical training used 16 × A800 80 GB; evaluation uses TP=4. See [environment setup](docs/REPRODUCTION.md#environment).

```bash
git clone git@github.com:ZZZRamsey/procvlm-repro.git
cd procvlm-repro
cp .env.example .env.local
# Fill external model, dataset, environment, S3 and NEW output locations.
set -a; source .env.local; set +a

# On each of four allocated nodes: set rank/master address/port first.
bash scripts/train.sh 1

# On one independent four-GPU allocation; NEW evaluation output directory.
bash scripts/evaluate.sh "$STAGE2_MODEL" test_full 64 4
```

Weights, datasets, media indexes and credentials are **not included**. Prepare them before running; nothing is downloaded implicitly. The [full report](docs/REPRODUCTION.md) includes Stage 2, resume, data layout and output conventions.

## Explore & check

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/render_metrics.py
python3 -m http.server 8000 --bind 127.0.0.1
# Open http://127.0.0.1:8000/visualization/ — static, self-contained; no private service needed.
```

GPU checks and full rescoring require the external environments/data. Their **actual status and limitations** are recorded in [VALIDATION.md](docs/VALIDATION.md), not implied by the historical results table.
